# 0.2.3：基于使用记录减少额外格式纠正

本轮是使用数据的优化审查。`0.2.2` 启用后当时只有一个成功请求，没有新失败；优化依据包括此前保留的拒绝样本，重点是减少不必要的模型格式纠正，而非为一个不存在的新报错扩大重试或放宽参数校验。

## 本地解码

规范 JSON 和规范 DSML 继续使用现有快速路径。DSML 规范解码失败后，新增受限状态解析器，识别已有样本中的边界写法：

- 匿名结束标签关闭当前已显式声明的参数或调用。
- 带有显式名称和 string 标志的下一参数误带 `/`，按照这个明确边界读取两边的完整值。
- 参数结束标签重复写了同名属性，或在已关闭参数后重复了空结束标签。
- 所有调用已经关闭、文档最后的同名根结束标签漏写 `/`。

每个参数仍须显式提供名称和 string=true/false；字符串取原文切片，非字符串按完整 JSON 值解码。缺失值/类型、不完整调用、缺失终端根、重复参数、未知标签、嵌套工具协议及尾随正文继续拒绝。解析完成后整批执行原有名称、完整 Schema、tool_choice、并行限制和 SDK 多输出通道一致性检查，通过后才交付工具调用。

简短执行说明可出现在完整工具 JSON 前，继续作为 assistant content 交付，参数保持不变。这个路径仅接受受限执行说明和后续整个文档；文档示例、任意解释、代码围栏及不完整批次不适用。原先 DSML 前的执行说明采用同一识别规则。

## 数据验证

使用修改前的 `0.2.2` 源码快照作对照，重放 `.runtime/rejected-decisions/` 中保留的 32 个模型输出，采用先前实际捕获的 DSH 工具 schemas：

| 项目 | 结果 |
|---|---:|
| 旧版本已能解码 | 2 |
| 本轮新增可解码 | 17（来自 17 个请求） |
| 其中 DSML 边界变体 | 16 |
| 其中 JSON 前执行说明 | 1 |
| 继续拒绝 | 13 |

新增可解码样本逐个经过 SDK transport→标准 SSE→Completion 聚合。每份只需一次模拟 SDK 调用；整批参数哈希一致，DSML 字符串值保留原文，JSON 转义值与独立 JSON.parse 结果一致。没有真实模型调用，没有执行工具或续接原任务。源码测试只含合成文本，用户代码留在私有运行目录。

这证明上述已记录输出可以省掉后续格式纠正，不预测未来发生比例，也不将样本数量换算为已结算费用。生产请求仍报告实际的一次 SDK 用量；本地格式修复和本地响应重放分开统计。

重放结果位于 `reports/format-replay-20261022.json`。81 项回归覆盖原有能力及新增边界、长代码、显式参数类型、多通道冲突和示例拒绝。另进行有限次真实 Flash 验收以检查流式、原生恢复、工具决策和官方用量；结果与部署状态汇总于 `reports/format-optimization-validation-20261022.json`。

真实 Flash 的 3 次推理、1 次本地响应重放全部通过，没有格式纠正。该样本的首正文约 7.98 秒、终态约 9.06 秒；这验证正常链路，不能据此推断长任务或未来格式变体的发生率。服务已在连续空闲检查后切换到 `0.2.3`，ready，active/queued 均为 0，切换记录保存在 `reports/idle-reload-latest.json`。

本次不修改宿主历史、不增加模型重试上限、不压缩工具 Schema、不改变模型或推理等级。对无法明确解码的其余样本保留既有错误分类及有界纠正路径。
