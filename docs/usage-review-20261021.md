## 修复

### 在本地处理已观测的边界缺陷

仅兼容整个文档开头紧邻 `{"action":...}` 的单个 `<`。必须对全部剩余字符执行 JSON.parse，之后仍逐个验证所有调用名称、完整参数 Schema、tool_choice、parallel_tool_calls 与多输出通道的一致性。不会从解释文字中抽取 JSON，不猜补闭合符，不丢弃尾随内容或坏调用。工具数据的字符串内容不做替换。

真实失败输出通过 SDK transport 的离线模拟重放：一次模拟推理即返回完整工具调用；预期/收到的整批参数 SHA-256 相同；没有真实模型请求，也没有执行任何宿主工具。见 `reports/usage-review-replay.json`。原始用户代码没有加入源码或测试 fixture；常规测试使用合成文本。

### 缩小付费纠正轮的输入

普通语法错误的纠正继续引用同一原生会话中的完整工具定义，不再每轮发送全部 schemas。本次参数下，常见纠正提示从约 6,897 字符缩小到不足 1,000 字符，要求保留原有参数值并完整返回所有必需字段，不能用占位或引用代替。该差值只说明新增提示长度，不是整个模型输入或费用降低的比例；精确大小记录在重放报告中。

Schema 错误会明确指出缺失字段/期望类型。只有实际失败工具的完整 schema 再次发送；其它工具与宿主上下文继续复用，不截断说明、不删减约束、不填造参数。不变更模型、effort、最长两次额外纠正及原请求期限。相同坏输出提前停止、失败请求断路仍保留。

### 为下次复核保留足够证据

每个被拒绝的尝试均记录错误分类、输出长度/哈希、纠正提示长度与重发 schema 长度，终轮失败也标注错误。已知凭据脱敏后的模型输出另外保存在 `.runtime/rejected-decisions/`，最多 32 份、共 8 MiB；单份超过 1 MiB 时降为摘要。该目录只清理自身生成命名空间内的普通文件，不处理手工文件或原有终态错误证据。常规日志不保存原始输出。

`/metrics` 和 CLI 新增 `localDecisionRepairs`、`correctionTokens`。纠正用量只包含额外尝试，不重复加入首轮；同时报告缺少尝试详情/用量的记录数。本地格式修复与本地响应重放分别计数。

## 验证边界

离线回归覆盖原有能力及新增的完整文档兼容、尾随/截断拒绝、Schema 与多通道冲突、定向纠正、本地一次推理返回、token 分拆及私有证据脱敏/容量限制。另执行有限次真实 Flash 验收以检查流式、恢复上下文和用量字段。

离线原样重放能证明该已记录输出可以在本地恢复；不能证明历史更早的首次坏输出也属于同一种缺陷，也不代表未来所有格式错误都会消失。此轮修复不续接或重新执行原先失败的用户任务。
