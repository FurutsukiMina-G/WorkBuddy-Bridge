# 0.1.1：修复长任务首步 invalid_decision

已更新本机正式安装，由原 `WorkBuddyBridge-8647` 计划任务运行。

## 根因

按原失败记录重放后，腾讯官方 SDK 返回了 `success`，输出是两条完整 DSML `read` 调用，而旧桥只执行 `JSON.parse`，因此拒绝了有效的模型工具决策。随后捕获到另一种输出：简短执行说明加同样完整的 DSML 调用。

## 改动

- 严格解码完整 DSML calls/invoke/parameter，不补全残缺边界、不丢弃后续调用、不做参数类型强制转换。
- 保留多调用顺序、字符串参数、中文、引号、换行和代码；解码后继续验证完整 JSON Schema、声明工具名与 tool_choice。
- 接受已识别的简短执行说明前缀，并在整批校验通过后作为 assistant content 交付。普通说明/代码示例不被当作调用。
- 统一收集 SDK result、assistant 文本和已经结束的文本流块；输出通道矛盾时明确拒绝，不挑选其中一条执行。
- 解析失败也转发 SDK 已报告的用量。私有 `.runtime/decision-errors/` 保存脱敏生成输出和请求 ID，健康接口仅暴露长度、哈希和证据路径。
- 不增加格式重试、不切模型，推理继续使用已核实的 WorkBuddy DeepSeek Flash 官方 SDK 链路。

## 验证

- 40 项本地测试通过，新增长中文 TypeScript、两条 DSML 调用、进度说明、参数类型、重复/缺失/截断边界、原子整批验证、输出通道一致性及失败用量证据的回归。
- 捕获的原始失败输出已离线验证：旧 JSON 解析失败，新解码器得到两条通过 Schema 验证的 read。
- 正式服务重放两份原始失败请求：均成功返回两条 read 调用，分别约 11.5 秒与 12.1 秒。两次均为单次模型推理，没有额外格式纠正请求。
- 重放只检查接口返回，不运行 DSH 项目执行器，不执行任何返回工具。原任务目标文件前后 SHA-256 一致。
- 此次未启动耐久测试；之前的耐久测试保持用户停止状态。

原始任务、SDK 返回和带项目路径的证据只留在本机私有排障目录，不包含在源码包内。可回滚快照位于正式安装的 `.runtime/fix-backups/invalid-decision-20261021-070623/`。
