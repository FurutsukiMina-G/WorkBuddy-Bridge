# 0.3.1：原生模式审查修复

保留 0.3.0 的原生宿主函数、上下文增量复用、缓存统计与运行时预启动。修复四处可复现的回归：

1. **完整文档解码**：原生模式遇到文字调用时，把完整回复交给严格 JSON/DSML 解码器。此前从首个协议标记截取尾部，会丢掉“下面是调用示例，请勿执行”等前言，并把示例交给宿主执行。现在仅接受解码器原有的有限执行前言；已流出的合法前言保留原始换行，避免重复。
2. **确认调用批次结束**：必须验证运行时初始化，并收到成功 Result，或明确的 `Max turns (1) exceeded` 异常。若 SDK 异常带有多条原因，每条都必须是这一停止原因。普通传输错误、11128、错误 Result、缺少终态的 EOF（包括已经收到 message_stop 的 EOF），都不能把已收到的调用前缀当成成功批次；不转发工具调用，不输出 DONE，不盲目重试，保留已知 token 与缓存用量。
3. **跨行、跨片段拦截**：调用信封与宿主参数对象的首个 JSON 属性可以跨行、跨任意流片段。闸门在辨明首个属性前保留对象头，支持空白、CRLF 与转义属性名。围栏、行内示例和普通业务 JSON 的处理保持兼容。
4. **显式 JSON 回复**：`response_format.type` 为 `json_object` 或 `json_schema` 时，文字按回答原样流出；即使含有 `action`、`calls`、宿主参数名或 DSML 示例，也不拆成旧桥协议、不推断工具动作。真正的原生工具调用仍按原 Schema 与 tool_choice 校验。`response_format: {"type":"text"}` 保留普通文本的调用拦截。

## 验证

- 115 项本地回归通过，包含四处问题的传输级用例、每个字符分片及所有单次拆分位置、合法执行前言、错误终态与混合异常原因、显式 JSON 两种格式；已有原生并行、续接、预启动、流式输出、用量与 JSON 兼容模式测试保持通过。
- 原审查的六个复现用例重新执行：说明示例、多行参数对象被拒；传输错误、11128 与 EOF 不返回调用或 DONE；显式 JSON 正文逐字保留。全部使用模拟 SDK，无宿主工具执行。
- 真实 WorkBuddy Flash 验收 `npm run native:smoke` 的 6 次请求全部通过，0 次纠正重试；覆盖原生顺序调用及热续接、并行调用及热续接、最终回复逐段流出，以及含旧协议字段的业务 JSON。2 次续接命中预启动，就绪耗时分别为 500 / 586 ms；输入缓存分别命中 4,352 / 4,562 与 4,352 / 4,603 token。流式正文约 4.99 秒开始、6.51 秒结束。宿主结果仅为固定验收字符串，桥不执行工具。

运行时仍依赖固定 SDK `0.3.286` 的停止行为。显式 JSON 模式保留模型正文，不额外承诺模型输出必然符合调用方的业务 JSON Schema。
