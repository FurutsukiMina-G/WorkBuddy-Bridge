# 0.2.2：最终回复换行与超时统计修复

## 实际故障

2026-10-22 UTC+8 00:00 和 00:02 的两次失败均为完整 `action:final` JSON 文档中的实际换行未转义。旧增量解码器已经交付开头正文，但遇到换行后停止投影；终态 JSON.parse 抛出控制字符错误。因为正文已交付，纠错保护拒绝再次生成，宿主收到 invalid_decision。

另一个请求达到 300 秒总期限，前两个已完成尝试的 SDK 用量已留在尝试记录里，但取消中止了 SSE 读取，顶层 usage 仍为 null。该请求至少已报告输入 123,284、输出 43,667 token；第三次未报告的部分无法补算。

## 修复行为

- 有效 JSON 先走原有 JSON.parse 快速路径。只有解析失败时才扫描 JSON 字符串中的实际 U+0000–U+001F 字符，将其编码为对应 JSON 转义后重新解析完整文档。解码后的换行、回车、制表符和其它字符保持原值。
- 流式 final.content 投影直接保留同样的实际控制字符，因此正文能连续流出，并与终态结果一致。引号、反斜杠、Unicode 代理对仍按原规则解码。
- 不补未完成的字符串/对象/工具批次，不猜测反斜杠后物理换行的“续行”含义，不改变工具类型或参数值。完整 Schema、tool_choice、输出通道一致性及截断检查保持生效。
- 传输层在 SDK 用量到达或尝试结束时更新已知官方小计。HTTP 超时中断读取后，服务仍可记录这份小计，并在可写的错误流中发送 usage，再发送错误；不发送成功 finish/DONE，也不重复发送已交付的 usage。
- 历史记录顶层 usage 缺失时，metrics 从已记录尝试/传输快照读取小计，不修改原文件；`incompleteRequests` 和 `recoveredUsageRequests` 分别显示不完整统计和读取恢复数。未知的最后一次尝试继续保持未知。
