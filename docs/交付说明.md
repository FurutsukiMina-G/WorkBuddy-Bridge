# WorkBuddy Bridge 已接入 DSH

**2026-10-21 更新至 0.1.1：已修复长任务首步 `invalid_decision`。** 原因是模型返回 DSML 而旧桥只接受 JSON。现兼容完整 DSML 与调用前的执行说明，保留整批工具 Schema 校验；40 项本地测试通过，两份原失败请求在正式服务均重放成功。未执行其返回工具或改项目代码。见 [修复记录](invalid-decision-fix-2026-10-21.md)。

在 DSH 模型选择器中选择 **WorkBuddy Bridge · SDK**，provider 为 `workbuddybridge`，默认 Flash 条目为 `workbuddy-deepseek-flash`。原有 `workbuddy` 分组仍属于旧插件，默认模型未被本次安装改写。

正式推理使用腾讯官方 Agent SDK 驱动本机 WorkBuddy 运行时；保留官方系统提示与请求处理，将 DSH 上下文作为结构化输入。桥返回经完整 JSON Schema 校验的工具决策，由 DSH 执行工具。实时目录已核实上游为 `deepseek-v4.1-flash`，不自动切换模型或账号。

`11128` 作为渠道校验错误单独保留，不通过盲目重试或反复刷新 token 掩盖。当前真实 DSH 两轮工具任务均通过，尚不能把短时验收当作数小时稳定性的保证。

已完成的验收：

- 21 项本地回归、语法检查全部通过。
- 模拟 8 小时内多次 token 到期刷新、并发单飞、重启恢复与重新登录恢复通过。
- 正式服务的 DSH 原生 `read`、`pwsh` 均完成工具调用、随机结果续接与完整终态。
- 工作进程崩溃约 3 秒恢复；守护进程自身退出时一并回收 worker，避免旧进程占端口。
- 修复真机 SDK 子进程残留；多次请求完成后无残留 SDK 子进程。
- Windows 计划任务 `WorkBuddyBridge-8647` 已启动，当前用户登录自启，无执行时长限制，并带心跳检查与崩溃恢复。

耐久测试已按用户要求停止，后续由用户实际使用验证。停止前的记录保存在本机私有 `.runtime/` 目录，不视为已经通过 6 小时验收。桥接服务与登录自启任务继续正常运行。

```powershell
& .\scripts\stop-server.ps1

```
